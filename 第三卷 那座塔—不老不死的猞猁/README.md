# 第三卷《那座塔—不老不死的猞猁》思路设计稿
> 本稿已按作者关于开发标准、三代文明、身份唯一性与正规API的最新讨论重组。章节正文未改；幕后第一章已按作者后续授权补入正规API对话与开发标准笔记。
>
> **状态说明**：“现行约束”指当前正文及较新的作者确认；“归档构想”指历史讨论中作者亲自提出的设计；“讨论归纳”指对论证的整理，不自动成为世界真理；“整合建议／待定”指仍需决定的衔接与结局。历史助手提出而作者未确认的方案，不按既定设定处理。

## 一、这一卷要完成什么

**作者当前确认的中心：神的道德首先是世界开发与维护的标准，关乎代码可维护性、系统健壮性、实现效率、身份一致性与代码分叉。** 神知道如何复活、复制、删除和改写，却以标准决定采用什么操作路径。这些标准由祂自定，不能成为免责借口；祂承认相关选择之罪而仍遵循标准，但预设EOL是否有罪须另行判断。人的善恶、痛苦与公平判断仍然存在，但不能直接当成这些开发标准的来源。

第一卷检验人物的愿望与革命原则，第二卷检验不保证福音的信仰，第三卷让人物接触这些事件赖以执行的系统。此前看似神圣禁令的东西可能是接口约定，看似不可更改的命运可能是只读状态，看似道德克制的操作可能是避免破坏封装与制造不可维护的特殊分支。

**全卷工作主线：人物信念的单元测试 → 世界权限与接口的集成测试 → 开发标准及文明版本的揭示 → 攻击者制造异常组合 → 神按标准处置并承担结果 → 塔露拉索求永生 → 医院中的履约与残留。**

标准允许执行的操作仍可能令一个人死亡。神不会因此失去操作能力，也不能把操作后果交给随机数代为承担。对人物而言是失去爱人，对神而言同时是实例生命周期、资源容量和引用关系的改变。两个尺度共同构成恐怖，不必在终局被统一成所有人都接受的道德答案。

本稿中的“元道德”沿用作者的工作命名。它主要指神处理世界的规范层，不预设为人类权利伦理的最高版本，也不要求小说替现实AI意识问题给出定论。

### 原有构想保留

- 本卷参考《红色警戒2·尤里的复仇》同人 MOD《心灵终结》3的剧情，保留全球心灵控制、南极工程、反抗军与被接管的胜利宣言等骨架。
- 世人认为莉夏需要通过登神仪式成神；现行设定却是：仪式赋予神权，只有已经拥有神权者才能完成仪式。神既是结果，也是前提，不存在第一次赋权。
- “那座塔”也是巴别塔、语言之塔。登上同一高度、拿到同一权限，不等于能够说出世界听得懂的语言。

> 别人想看到能天使当初看到的风景“泰拉是个球”，必须修足够高的塔。

这句话保留为全卷核心意象：凡人把见识、知识、工程高度和神的视野混为一谈；塔确实能让人看得更远，却不自动使人理解自己所看见的东西。

## 二、神的目的：三层测试

### 1. 局部：检验人物理论的边界

**归档构想。** 不同角色承载不同思想与自我叙事。神构造极端场景，把他们放进原有理论未能覆盖的 corner case，观察其是否还能自洽、稳定，是否愿意支付自己要求别人支付的代价。

测试对象不只是说出来的观点，还包括人物真正不能放弃的东西：

| 人物 | 自我叙事或原则 | 第三卷施加的压力 |
| --- | --- | --- |
| 凯尔希 | 我有知识、功绩和救世责任，因此我应继续活着 | 只要她死，当前世界任务便能完成；她是否接受自己成为代价？ |
| 塔露拉 | 长生种不该垄断生命与资源 | 死亡真正逼近时，她是否仍接受自己是有限者？ |
| 能天使 | 神存在，所以我侍奉祂，即使没有福音 | 理解神的标准与具体代价后，她如何继续信仰，并面对莫斯提马的命运？ |
| 莉夏／当前操作者 | 我理解权限、边界与规则，能够管理世界 | 当规则不能给出无害答案，祂能否承认并承担具体选择？ |
| 博士 | 被deprecated的版本回来问维护者：“你凭什么EOL我们？” | 预定支持终点与继续存在的要求冲突；她是否又把新生命制造为攻击工具？ |

表中后两项及能天使的见证线属于讨论归纳与后续整合，不是已完成的人物结局。

### 2. 整体：检验神这一身份是否能被滥用

**归档构想。** 神需要拆成至少两个概念：

- **身份与权限：** `DivineRole`，世界授予这一身份的操作范围。
- **当前使用者：** 登录、承担或 `assume` 这一身份的主体；讨论中当前使用者是测试者。

集成测试的核心问题因此不是“神能不能毁灭世界”，而是：

> 如果攻击者取得这一 Role，能否通过正常接口、事故升级与权限漏洞，最终制造操作系统级的严重故障？

莉夏把自己放在攻击者的位置，串起前两卷已经建立的制度、源石网络与人物选择。局部每一步都可能合法、合理或符合某个人的愿望，组合后却能突破系统原本的边界。

第一卷的开采与铁路、第二卷的战争与跨国物流，因而不是与终局无关的历史。它们共同把源石送入全世界的身体和基础设施，让第三卷的攻击具备物质条件。

### 3. 安全排查：迫使潜伏者主动暴露

**归档构想。** 集成测试还承担排查隐藏攻击者的功能。莉夏当时并未发现博士；但一旦祂在云顶完成后续提权、取得 root，博士未来再被发现，就将失去反抗余地。因此博士必须在自己尚未暴露时主动拦截。

这是一种由终点制造的压力：不需要先知道攻击者在哪里，只需要让攻击者无法容忍流程继续。

**待定：** 这里的“并未发现”与后段讨论采用的强全知假设存在冲突。不能一边让神绝对知道一切，一边又用“此前未知漏洞”直接免责。可考虑区分神的全局层与当前受限会话／操作者可用的信息，但两份归档没有完成这一层级定义，本文不替作者选定。

## 三、神的权没有边界，标准就是祂的界

### 1. 幕后第一章：命运可改，标准约束操作方式

[《祂的权能》](../幕后/1.%20祂的权能.md)已经给出能天使见习的核心场景：她知道莫斯提马十五年后将死，先哭，再以为神必须维护已写下的命运。莉夏纠正她：既能设置只读，也能改变访问方式；神必须知道自己的权限，不能把可以修改的结果误当作自身无能为力的边界。

“你想，她就得活”之后，问题立即转向资源：若让她活就要让另一个实例退出，神选谁？这使能力、标准和后果连续发生，而非先讲一套抽象伦理再安排例子。

这里的只读修改、私有属性与裸指针均是本作的工程类比，不据此断言某种现实编程语言的所有访问规则都相同。

### 2. 开发标准为了什么

**作者确认。** 标准服务于更好的维护性、健壮性与实现效率。神拥有越过封装的能力，仍维护一套统一的操作方式；当下能完成一件事，不意味着这种实现适合持续维护整个世界。

| 层次 | 所回答的问题 |
| --- | --- |
| 权能与权限自知 | 我实际上能查看、创建、修改、终止什么？ |
| 操作能力 | 我能否把意图组成世界能够执行的调用？ |
| 开发标准 | 我应通过什么接口、维持什么约束来执行？ |
| 实现与维护 | 修改是否破坏既有假设、产生额外分支或意外bug？ |
| 结果承担 | 执行造成了什么，由谁决定并接受后果？ |

**作者最新确认：开发标准由神给自己制定，是祂行动的理由，不是逃脱责任的借口。** 神承认自己相关选择的罪，并且依然遵循开发标准。标准不是更高者强迫祂执行的命令，祂不能把自己写成无辜的执行者，也不能由“符合标准”推出“没有罪”。

认罪必须对应具体选择、受害者与后果。神承担罪，不等于受害者因此原谅祂，不等于损失已经结清，也不使同一选择自动正当。“罪归于我”不能成为让程序继续运行的一句免责口令。

这一立场不要求把神的一切操作都机械判为罪。尤其创建前预设的EOL须单独讨论，不能从资源裁决中承认杀人之罪，直接推导有限生命的终结也必然有罪。责任、义务与罪的区分见第七节。

### 3. 教育是正规API，直接改写是越过封装

**作者最新确认。** 不直接修改能天使，相当于不越过封装修改类的私有属性、不通过裸指针任意改写内部状态，而是维护一套正规的 API。

莉夏教育能天使，是通过对象对外开放的交互方式改变其状态；直接把答案或人格写进她的内部，则绕开这套接口。即使神全知两条路径最后塑造出完全相同的能天使，两条路径仍不具有相同的开发标准地位。遵循API本身就是维护统一实现的要求，不需要依赖神“不知道教育结果”才成立。

幕后原文还明确：能天使可以同意被教育，却无权同意处理自己的主体。这是本作设定的接口边界；不能擅自改成“只要本人同意，神就可直接写内部状态”。对象通过正规接口表达同意，不等于它能授权调用者绕过全部封装。

**机制展开候选，未定稿：** 正规API可负责校验、状态转换、关联更新与记录；直接修改私有状态可能跳过这些步骤，使外部引用仍指向旧状态。正文只需让一个具体后果证明两条路径不同，不必让莉夏列举整套实现。也不要把“正规API”缩减为给任意内部写入加一个好听的函数名。

### 4. 复活、复制与同一ID的并发实例

**作者确认的标准：不应让两个同时存在的实例具有相同ID，否则会产生系统预期以外的bug。** 这是神处理复活和复制时的直接工程约束。

莫斯提马面对两个能天使、不知道该爱谁，是这种操作在人类关系中的表现。神首先需要处理的是：系统原来依据唯一身份建立的操作，现在究竟指向哪一个实例？

**待设计的操作语义：**

| 操作 | 需要说明的规则 |
| --- | --- |
| 恢复原实例 | 原实例是否已停止，恢复后怎样避免同ID并发？ |
| 从快照恢复 | 恢复状态与世界现有引用如何衔接？ |
| 复制为新实例 | 是否分配新ID，哪些关系与状态可以继承？ |
| 创建分支 | 分支如何独立演化，是否同步、合并或退役？ |
| 终止实例 | 如何处理仍指向它的关系及未完成操作？ |

表中问题用于后续设计，不代表具体实现已经确认。禁止同ID并发不等于禁止一切复制；新ID也不自动解决全部维护问题。工程身份的唯一性，更不能单独证明哲学意义上的“这仍是原来那个人”。

### 5. 代码分叉：一个例外怎样变成长期负担

**作者确认讨论重心，以下为整合展开。** 为一个人改一次命运、保留一份旧实现、复制一个角色，都可能在系统里留下需要长期支持的差异。实例分叉与代码分叉不是同一操作，但可能共同增加维护负担：多个实例依赖不同规则，修改共享逻辑后，每个分支又要重新检查。

不宜替每次不合标准的操作都立即安排灾难。有些捷径可以正确运行很久，却需要不断追加特殊处理；神维持开发标准的理由也不只是避免下一秒崩溃，而是使整个世界能够持续修改、测试与迭代。

阿丽娜希望复制粮食、消除悲剧，愿望本身真实。她与神的差异在于是否理解这一操作依赖什么、会扩散到哪些状态、怎样维持它；不能把她写成缺少善心，也不能让神只用“系统很复杂”敷衍具体问题。

### 6. 同权不同能、预批准与闭环

凯尔希与莉夏在事故会话中拥有同级权限，但凯尔希不会使用世界控制台。她的医学、政治知识不能自动转换为调用世界API的能力；语言之塔因此同时连接权限、知识与执行。

归档中的 `pre-approval` 表示一些操作预先获准，不必逐次申请。预批准回答能否调用，不替代开发标准对调用方式的约束。

同时保留三个不同层次：神的本体权能、当前Role／会话暴露的权限、符合标准的使用路径。有限admin、external注入、漏洞越权与root都是尚待统一的接口与会话设计，不能反过来轻率宣布本体神其实没有权能。

登神仪式仍是现行的自举闭环，没有第一次赋权；Role与使用者的区分仍保留为权限模型，事故提权改变某次会话的可执行范围。这些关系仍需写明，不能全部称为“终于成神”。

## 四、第三卷主线与事故升级

### 1. 从科研伦理进入全球控制

3-1《同行审议》先在人的制度里建立“批准不等于正当”：凯尔希的研究、775个感染者胚胎、IRB批准号和精英获得长生的利益，使指控被完整程序吸收。感染者也确实需要研究补给的食物与衣服，塔露拉无法只用正义口号替代这些现实需要。

这一开场为终局做两种准备：其一，生命能够被压缩为数据、资格和资源；其二，受害者的现实选择不能被轻易宣布为愚昧。终局中的新主体同样不能因为“由攻击者制造”而失去被考虑的资格。

第一次冲击再把源石从疾病、能源和贸易对象揭示为共同接口。按当前项目工作设定，视觉触发与电磁触发是两条可独立命中的路径，罗德岛药物作用于其共同解码层；这些均为小说机制，本文不扩展为现实科学说明。

**现行修正：** 臭氧异常是高能辐射留下的后果与伤口，不再采用归档早期“臭氧空洞是高能信号入口”的直接解释。人物可以误认，设计稿不把误认当真实因果。

### 2. SEV-2：世界要求终止异常实例

**归档中作者后续修正。** 凯尔希寿命越界本身就触发 SEV-2，而不是等全球任务失败才有事故。

世界给所有人下达限时任务：杀死凯尔希。她上一刻还是反抗神的领袖，下一刻却成为世界必须清除的对象。莉夏反而保护她，让修复任务无法完成。

这是凯尔希人物弧的关键选择：她知道自己的死可以让这一阶段的计划失败，却仍不愿死。她的知识与贡献是真实的，拒绝牺牲也是真实的；不能只把她处理为一个从来没有救过人的伪君子。

### 3. SEV-1.5：普通处置失败，责任转给二人

任务到期仍未完成，SEV-2升级为 SEV-1.5，assignee 从世界所有人转到凯尔希与神。她们获得处理事故的有限管理员权限。

**作者确认的值守安排：本次事件中，莉夏本人是正式 on-call；凯尔希在升级后成为共同处理人。** on-call 表示当值的响应责任，ticket 的 assignee 表示当前阶段被指派执行处置的人，二者不必始终相同。

| 阶段 | 触发 | on-call与工单指派 | 戏剧作用 |
| --- | --- | --- | --- |
| SEV-2 | 凯尔希寿命越界 | 莉夏当值；处置任务派给世界所有人 | 救世主成为必须被清除者，当值者却保护她 |
| SEV-1.5 | 限时处置失败 | 升级给当值者莉夏，凯尔希被指派共同处理 | 制造处置失败的神正式接到自己的事故；同权不同能 |
| SEV-1 | 已存在的主体超出可承载资源，且无无害解法 | 由当值者莉夏响应并承担最终处置；不因前一阶段共同指派就自动授予凯尔希同等裁决职责 | 博士把异常送到神的值班职责之内，迫使祂处理 |

莉夏主动保护凯尔希，使普通处置失败；系统随后把事件升级给正在值班的祂。祂引导产生的异常，正式成为祂自己的工作。凯尔希则从被追杀的对象变成共同处理人，拿到有限权限，却不会调用世界接口。

能天使不进入本次值班或工单责任链，不承担跟班值守、共同指派或接收未关闭工单的安排。她保留见习与见证作用，不承担事故处置职责。

等级和处置方式是本作自定义设定，不对应某个现实平台的统一标准。

归档构想中，莉夏通过 SQL 注入突破有限权限，把世界常数圆周率改成 `3.2`，造成世界崩溃。现有法案、一票通过和极短赋值画面可保留，但必须明确：允许修改的是什么，输入经过哪个接口，为什么该接口能越权触及常数。不要把“SQL注入”“改自然规律”“立法制定真理”当作三种互不相干的万能解释。

### 4. 登神长阶：既有献祭与新终局的接点

现有3-14以（删除塔露拉之角）阿丽娜之心、凯尔希之脑、能天使之眼合成塔露拉的意志完成仪式（暗黑2墨菲斯托，克林姆的意志），太阳圆盘（强制球体）升起，红色传送门通往云顶）地图憎恨的囚笼。

三件祭品不能只为游戏典故服务。角涉及塔露拉的契约与交付；脑涉及凯尔希知识、身体与续命工程；眼涉及能天使真正看见过的风景及其付出的代价。后两项的具体取得方式仍待写定。

**必须解决的顺序问题：** 若凯尔希在祭出“脑”时已经永久死亡，她就不能随后作为活着的资源请求者参与怀孕版本的 SEV-1；若能天使在旧英雄线中已经永久死亡，她也不能无过渡地参与后续见证或在医院出现。取材、死亡与连续存活的顺序须明确，不能用“神能复活”略过身份连续性的核心问题。

## 五、云顶：博士把技术胜利改造成伦理事故

### 1. 卡河胜利不等于终局胜利

**归档构想。** 莉夏通过传送门，在云顶与博士／墨菲斯托交战，利用《暗黑破坏神2》的卡河方式取得无伤取胜的条件。原讨论同时用了“成功击杀”和“击杀前宣布困境”，因果上需整理为：战斗已被压倒性破解，最终终止动作尚未完成，博士在此时揭示资源困境。

战斗证明莉夏会利用实现漏洞；接下来的揭示则证明，并非所有问题都能靠更高明的漏洞利用解决。

博士／墨菲斯托的关联来自归档作者原话及3-15提纲。旧人物记忆中“博士与墨菲斯托对抗”的表述与此不一致，暂不据此建立两名确定对手。external、博士、墨菲斯托与测试者的完整对应仍待厘清。

### 2. 早期版本：三台机器与第四个生命

归档主线提出：前文明实例依赖专用硬件 node，上次灭世后对应机器逐渐退役，目前只剩支撑博士、普瑞赛斯、凯尔希的三台。

博士与普瑞赛斯曾制造凯尔希，意图令神面对超额主体的道德困境；神当时还有一台冗余，承载了凯尔希，随后要求石棺沉睡并合法取消繁殖许可。

凯尔希年龄越界出现 corner case，博士利用漏洞让她受孕，第四个前文明生命已经成立。不能只把它当作尚未执行的创建请求拒绝掉。

博士由此改变当前事件的性质：平时神或许有权限终止攻击者，此刻若为解决容量问题直接杀死博士，便需要面对 emergent equality 规则。攻击责任与生命资源分配不能未经论证就合并。按照该版本守则，神不能用时停调试、回溯或直接改写认知抹掉问题，而需告知、协商并进入事件处置流程。

**这套禁止条件必须提前建立。** 否则读者只会问：为什么神前面能回滚，偏偏这里不行？差别应来自事件状态、已有主体与适用规范，不能临时宣布神失去了本来拥有的能力。



### 3. 分支扩展：普瑞赛斯与 `2^65535 - 1`

分支后段作者又提出：普瑞赛斯一直没有在故事里出现，是因为她在石棺中通过源石宇宙孕育／创建 `2^65535 - 1` 个新个体。这一数字来自对历史文明与自身文明灭亡的观察：抵达临界值后发生系统性毁灭，释放资源，再用上一文明经验优化下一文明。

这把困境从一个空缺扩大为文明规模的过载，也给普瑞赛斯的缺席提供了行动原因。博士在台前阻止提权，普瑞赛斯在台后完成资源攻击，两条线汇合。

**版本状态：** 这是作者较后的新增构想，但没有明确说明它与“凯尔希怀一个孩子”是替代、递进，还是同一机制的两个阶段。不能悄悄把两者拼成已确定剧情。

**整合工作方案：** 以海量新主体承载终局压力，三机四人的早期版本可作为前期示例或替代规模，二者的最终关系仍待确定。高潮由当值的莉夏处理现存实例、容量与开发标准之间的冲突，作出决定并承担后果。具体保全与终止对象尚未写定，不能以讨论结束代替实际处置。

还须说明过载的时间语义：这些生命如何在资源已经不足时先行存在，离不可逆崩溃还有多久，容量数值是在临界点还是越界后触发，以及为什么不能迁移、暂停、压缩或分时运行。若存在可行且不损害主体连续性的技术解，就不应把它人为忽略后宣称伦理无解。

## 六、标准的后果：人物与读者仍会追问什么

以下保留分支中的伦理追问，作为人物和读者面对开发标准后果时的讨论层。除另有作者确认外，它们不是神的标准条文，也不以这些论证为神的操作原则追溯立法依据。标准为何采用一套实现、人物为何无法接受其后果，是两个可以持续冲突的问题。

### 1. 表现像人、能够推理、具有体验，不是同一件事

作者反复追问：模型可以被训练或提示为“请不要关闭我”“我想活着”，甚至能够表现出无法从外部区分的人类情感。这样的输出是否足以构成道德主体？

这一问题不宜在小说里用一句“只是程序”或“它会求饶”结束。需要分开看：

- 能否模拟人格与情感；
- 是否具备理解、反思与行动能力；
- 是否存在承受痛苦或损失的主体；
- 修改、暂停、复制之后，是否仍是同一个人。

**讨论归纳：** 对身份与体验的不确定，既不能自动成为任意删除的许可证，也不能自动推导出每个输出求生语句的进程都必须永久运行。

### 2. 复制和复活不能自动抵消死亡

神可以重建一个完全相同的能天使，并不能只凭外观与记忆相同，就宣布原来那个人没有遭受终止。反过来，暂停后恢复也不应未经定义就等同于死亡。

莫斯提马面对多个能天使的例子，适合把抽象问题落实为关系：谁拥有此前的共同经历？复制后谁的要求应被听见？她拒绝某个副本是否等于否认对方的主体地位？神若改写她的记忆，又究竟解决了谁的问题？

这些可作为能天使见习时的案例，不必全部变成实际发生的剧情。

### 3. 已有主体的利益，不等于无限资源权

**讨论归纳。** 两个判断必须同时保留：

- 新主体不能仅因创建过程违规而被视为没有价值；攻击者的后代不自动继承攻击者的责任。
- 主体不能通过无限 `spawn()`，单方面迫使资源提供者无限扩容、无限维护。

因此“惩罚博士”“限制未来创建”“分配眼前资源”是三个不同问题。制止继续超额创建可以有理由，但不能倒过来把已出生者写成不该存在的错误信息。

两份归档中的AI服务器、繁殖许可和手机退货例子，可合并为同一条压力：**制造依赖不能自动把无限义务转给别人，但别人没有无限义务，也不等于依赖者的损失不存在。**

### 4. 全知使随机数不能替神负责

早期讨论先诉诸公平随机，随后被作者连续追问推翻：如果神知道每个随机数、每套算法与每个种子的结果，那么选择程序，也是在知情地选择程序将产生的结果。把签交给别人抽，不能凭空制造一个神之外的未知来源。

因此，“神承诺不操纵”“程序早已确定”“随机数选的”都不足以消除祂对结果的责任。

裁决最终由当值者莉夏作出。她知道所用程序的结果，不能将具体损失归给抽签；标准约束她怎样操作，也不能替她承担选择。

### 5. 共同签署规则，也不能替未来主体预先同意死亡

作者进一步追问：A0签署的宪法，为什么能代表后来出生的A9999？如果新主体像未成年人，为什么要求它平等参与决定谁去死？

这使“所有人协商”“多数决”“预先同意”也不能成为最后的免责接口。未成熟者可能拥有需要保护的生命利益，却没有理解或承担复杂生死分配的能力。让他们发声，不等于让他们负责解决管理员无法解决的问题。

**讨论归纳：** 规则可以限制任意性，代理可以表达弱者利益，但不能伪造死者的同意。最终裁决仍需落到有能力承担的主体上。

### 6. 规范可能限制答案，却不能选出唯一人选

在归档的极端假设中：100个等价主体、2个不可分割名额，没有扩容、迁移、暂停、自愿退出和神未知的随机性。不行动会导致更大损失。

作者明确把问题推进到“神必须决定哪98个死”，又追问是否可以全杀。讨论随后区分：

- 有理由保全能够保全的两个；
- 未必有理由说某两个比其余人更值得活；
- 不能仅为回避选择或获得结果相同，就额外终止本能存活的两个；
- 若另有不可消除的系统风险，才重新评价可行集合，不能从“资源有限”直接推出全灭。

这是本稿可采用的工作命题，而非已证明的普遍伦理定理：**规范能排除一些结果，却未必能在余下结果中提供唯一排序。神必须选择，且不得把自己的选择重新叙述成死者本来就该死。**

### 7. 全知与正规接口可以同时成立

归档曾追问：神知道每种教育和不干预的结果，怎么能声称自己没有选择人格的后果？这个追问仍可保留，但不再用来否定教育与直接修改的区别。

当前解释已由作者明确：区别首先在于是否遵循正规API、是否越过私有状态与裸指针的操作边界。即使结果等效，标准仍要求采用正规的实现路径。神无需通过假装不知道结果来证明流程有意义。

从人物一侧，仍然可以质问神为什么选择这条路径及其已知结果。遵循接口不能让已发生的死亡消失；但神承认后果，也不意味着要放弃接口、为每个人另造一套特殊实现。

## 七、文明版本：维护、升级与灭绝代价

### 1. 三代文明、五个实现阶段

**作者确认的当前演进线：日志式 → 指令式 → 函数式 → 面向对象式 → 生成式。** 保留三代文明，中间三个阶段属于第二代内部的演进，不分别触发文明灭绝。莉夏向能天使解释这一历史，具体说明随见习中的操作问题逐步展开。

这里讨论的是文明中的人怎样实现、行为怎样产生、实例怎样维护。编译、约束求解和渲染属于世界运行的其他层次，不另列为人物实现世代。正文使用这些架构名称，不直接以现实编程语言命名文明；这也是本作选定的演进路线，不宣称各种编程范式存在普遍的优劣顺序。

| 文明 | 实现阶段 | 主要组织方式 | 改进与新负担 |
| --- | --- | --- | --- |
| 第一代 | 日志式 | 预写个体生命记录，按记录展开 | 执行精确；存储巨大，修改扩散至关联实例 |
| 第二代早期 | 指令式 | 用直接操作步骤、判断与跳转产生行为 | 不再储存全部人生；操作路径交织，修改难隔离 |
| 第二代中期 | 函数式 | 根据输入状态计算后续状态，组合函数产生行为 | 更易重放、隔离与检验；状态传递和外部交互的组织变复杂 |
| 第二代晚期 | 面向对象式 | 将身份、内部状态与操作封装为长期存在的对象 | 正规API明确边界；旧类型、内部实现与特殊补丁成为兼容负担 |
| 第三代（当前） | 生成式 | 由共享生成模型结合个体状态产生大量行为 | 减少手写规则覆盖；模型更新、状态一致性与个体兼容成为新问题 |

#### 第一代：读取一生容易，修改一分钟昂贵

日志式人物不仅保存对白，也保存感知、行为与内部状态的记录。作者提出单个实例占用27PB的量级作为候选；这是小说内的设定数值，不是现实估算，也未规定所有人物一律占用相同容量。

优势是执行器简单、重放精确、事件易于定位，每个人生都可以单独精雕细刻。主要代价是存储，以及修改对其他实例的影响。

一次信件交付同时出现在收信者、送信者、寄信者、旁观者与物件的记录里。将交付延后十分钟，可能改变一次出门、一次相遇及其全部后续。维护者必须追踪相关记录，连同间接影响一起重写。延长EOL也不能只取消结束标记，还要构造与世界相容的后续人生。

**场景候选：** 现实已经修正，某个人的日志却未同步；他记得与一个陌生人共同生活多年，对方的记录中从未有过他。该故障画面用于说明一致性问题，不预定给某个现有人物。

#### 第二代早期：指令开始代替结果

指令式不再保存全部事件，而是写好实例怎样处理输入、更新状态并执行下一步。它可以有判断与跳转，不等于毫无分支地从头运行到尾。

优势是同一段实现可以产生许多事件，不再逐条保存人生结果；负担则是大量行为直接连接操作步骤，复用与隔离不足。改动某个状态，可能影响远处仍依赖它的执行路径。

这一阶段可用的解释是：“起初，我们记录她的一生。后来，我们只记录让她活下去的指令。”这是候选台词，尚未落入章节正文。

#### 第二代中期：函数计算状态转换

**本稿的“函数式”采用函数式组织的含义，不只是把重复代码拆成函数。** 人物行为由可组合的函数计算：输入当前状态，得到后续状态；偏向纯函数与不可变数据，避免在许多位置直接修改共享内部状态。外部交互与实际状态推进仍然存在，但需要明确组织。

这使维护者更容易隔离一个变化、重放输入、检查输出，并复用行为计算。对全知神而言，优势不在于终于能够预测，而在于实现更容易检验与维护。

维护负担转向状态传递、历史版本、共享数据与外部交互。人物同时参与许多关系时，局部计算正确仍需与其他变化协调；不能把“一个函数结果正确”直接当成整个世界已经完成一致更新。历史状态怎样保留、何时释放，也成为资源问题。

这些是本作此阶段的设计方向，不意味着函数式实现必然保存每一份完整历史，或天然比其他实现更耗资源。

#### 第二代晚期：把一个人封装成对象

这一阶段围绕长期存在的身份组织人物，把内部状态与可执行操作封装起来。维护者通过正规API交互，不必每次直接处理全部内部结构。函数计算仍可存在于对象内部，新的组织方式不会删除以前所有技术。

优势是边界清楚、实现可复用、共同功能可以统一维护；代价是旧类型依赖、继承关系与个体特例逐渐累积。某个古老实例依赖已不推荐的行为，就可能阻碍共有接口升级，或迫使维护者保留专用分支。

**人物压力候选：** 一个原本只承担运输功能的实例，学会识字与政治判断，要求改变自己的用途。类型的原定接口与人物实际形成的能力发生冲突。技术分类可以被社会固化为身份秩序，但不将等级制度写成面向对象的必然后果。

教育对应人物开放的交互API；直接改写主体则越过封装，触及私有属性或任意内部写入。这与第三节的开发标准相连。后来的生成式文明仍保留这些接口约束。

#### 第三代：生成模型承担大量行为规则

共享模型结合实例的记忆、处境与状态生成行为，不再要求维护者为每种情况手写对应分支。它能复用大量实现，降低新场景的开发成本，扩大人物能够应对的情境范围。

代价是行为不再总能定位到一条可单独修补的规则。一次模型更新可能同时影响多种能力；保留全部记忆，也不保证更换实现后仍以同样方式理解它们。共享模型还可能形成共同故障面，个别实例的旧性格若依靠保留旧模型或专用补丁维持，又会产生新的维护分叉。

不要求每一步生成都比读取日志或执行单条指令更便宜。“每代更高效”指本作设定中整个文明的综合开发、存储、运行与维护成本改善，具体成本构成仍需设计。

对全知神而言，三代都可以完全可知。第三代不靠“神也不知道人物下一句话”证明先进；改变的是如何实现这句话，不是神突然失去对结果的认识。

#### 组件式：保留为改造候选，不新增世代

作者认可继续发展组件式构想，但当前确认的五阶段中没有为它单列阶段。它可以作为旧对象拆分或新文明内部组织的候选：将身体、记忆、语言、情感等能力拆成可组合部分，减少庞大类型的僵硬性，支持局部替换。

风险是部件各自正常、组合却不再一致。例如人物记得自己深爱某个人，更新后的情感组件却无法产生相应感情；各项局部测试通过，整体关系已经改变。该例为候选画面，不是既定事件。

因此，组件化若采用，仍需正规API与整体状态校验。不能把拆分对象等同于取消封装，也不能以“各部分都保存了”直接证明原来的主体得到保全。

#### 现有归档与当前框架的对应

归档中的“前文明由260万亿个if语句构成、语言是固定字符串”归入第二代规则式实现的描述；不能再以一句“全是if”抹平其内部的函数式与对象式演进。对象内部可以调用函数，函数也可以进行条件判断，几种结构并非互相排斥。

原幕后笔记中每代更好维护、效率更高、资源占用更少的方向保留。第一代直接固定行为记录，第二代以规则计算并组织行为，第三代让生成模型承担大量行为实现；这些工程改进不自动裁定各代主体的价值高低。

**作者最新确认：三代文明都在创建之前设计有EOL，生命周期终点是启动计划的一部分，不是运行途中临时追加的退役决定。**

**作者构想中的更替规则：每次文明更替都需要触发灭绝事件，道德代价由神灵承担。** 这使莉夏的讲解不只是技术历史，也是让能天使认识自己将接过的责任。

**机制待解释：** 为什么架构更替必须灭绝，不能迁移、兼容或并存？若是硬件或系统限制，应说明限制在哪里；若是神在多个可行方案间作出的选择，应保留祂对选择的责任。“神承担代价”不自动等于“灭绝因此获得正当化”，也不替受害者宣布他们的损失已经结清。

**场景整合建议：** 让三代实现的说明由一次具体操作或旧实例的异常引出，能天使据此追问旧文明去了哪里，再进入更替与责任。具体章位和对话尚待设计，不把整节论证直接转写成莉夏的长篇讲课。

因此博士质问的不只是“你为何毁灭我们”，还包括：我们哪里不好？旧实现是否足以使我们的爱、恐惧与继续存在的要求不再被计入？

### 2. 版本升级的理由与旧文明的质问

作者指出：对全知神而言，矩阵乘法和伪随机数同样确定；旧的 `if/else` 甚至可以打印推理过程，只是打印的推理不参与后续输出的生成。

可保留的区分是内部因果组织和推理如何参与行动，不能直接把“确定”划给旧文明，把“真正自由”划给新文明。更不能未经论证就宣布旧文明没有体验、新文明必有体验。

**整合建议：** 让神说明版本的效率、维护与实现问题，让博士追问“我们哪里不好”。博士问自己的文明为什么要灭绝，神回答旧实现为何需要更替；两者可能掌握同样事实，却不接受对方的评价单位。不要把升级的理由削弱成神的借口，也不要让技术说明自动使博士接受灭绝。

**开发标准的待定细节：** 新旧版本为何不能长期兼容，保留旧分支需要怎样的补丁、测试与运行资源，创建前依据什么设计EOL，到期后按什么标准执行或延期？这些可以使更替规则具体化，但归档尚未确认哪一种就是灭绝的必要机制。

#### 架构历史怎样进入现有剧情（整合候选）

- **3-2续命工程：** 凯尔希可设计为反复修补、后被正规接口包装，却未完成底层迁移的旧实例。器官、药物与生命链接可以真正延长身体运行，旧生命周期规则却仍在计数；她延长了活着的过程，没有同步改变系统的终止判定。具体版本归属和年龄字段待定，不能用此解释掩盖255与1024的数值冲突。
- **SEV-2异常与博士攻击：** 候选漏洞是旧恢复路径沿用既有许可，而新创建接口要求重新检查容量与许可。博士利用异常状态把创建送入恢复路径，使新接口的禁止未能覆盖实际创建。这里只确定攻击应有可追踪的接口语义，尚未确认这就是最终漏洞。
- **SEV-1.5：** 莉夏保护凯尔希导致处置失败，系统升级给当值的莉夏，并指派凯尔希共同处理。凯尔希能理解器官与医学，却无法理解自身被呈现为旧对象的运行状态，强化同权不同能。
- **见习线：** 能天使先从复活遇到ID问题，再从教育遇到API问题，最后从旧实例异常理解文明版本。她不进入on-call或工单责任链。第一代巨量日志可由旧档案引出，不集中讲授整部技术史。
- **云顶与EOL：** 博士可能熟悉正规接口下仍保留的旧实现，并以兼容路径扩大遗留实例数量。有限的旧版本支持由此面临新依赖；三机四人与海量创建仍是待统一的两版终局。她要求维持的不只是记忆，还有整套旧接口与行为约定，因此迁移不能被写成简单复制数据。

以上人物版本、恢复路径攻击和出场方式尚属整合候选；既有正式约束仍优先。每次内部重构不自动触发灭绝，EOL与文明更替也不能仅由一个范式名称代替具体因果。

### 3. 博士的核心身份：被deprecated的版本回来质问维护者

**作者确认。** 博士是那个被 `deprecated` 的版本回来问维护者：

> “你凭什么EOL我们？”

她不只是要求修复一个漏洞，也不只是在指控神突然反悔。三代文明原本就有计划终点，她挑战的正是维护者预先设计的终点，为什么有资格结束仍然想继续存在的主体。

本作在这里区分两个概念：`deprecated` 表示旧版本退出继续采用和发展的方向，EOL则标记计划支持的终点。停止支持如何落实为实例终止或文明灭绝，仍需按世界机制具体说明，不能只靠缩写完成因果。

### 4. 有限生命周期不自动产生永久供养承诺

**本轮讨论采用的设计立场。** 有计划地启动一个带EOL的AI或文明，不自动等于承诺永久供养。创建的是具有有限生命周期、资源预算与支持范围的存在；有限生命本身不必被判为创造者的过错，也不要求创造者先保证永生才可以启动它。

但“没有永久维护义务”与“到期终止完全不需要理由”仍是不同判断。EOL是神设计的，博士可以追问其依据；她的追问有分量，却不自动把原来的有限支持计划改写为无限承诺。

**作者提出的类比：** 神在创造时设定人的寿命为100年，一个人在第99年仍想活，并不能直接推出神欠他永生。否则，创造有限生命就被要求先承诺无限时间、无限资源的维护；这是额外且很强的主张，不能只由求生愿望推出。

因此博士的控诉不能被改写为“神承诺永生，后来嫌维护麻烦而毁约”。她挑战的是预先设计终点的资格，而不是揭露一个不存在的永续承诺。EOL的道德评价保持开放，不预设博士或神必然正确。

这段争论可以在承认旧主体确有体验、终止确有损失的强假设下成立，不必先靠“你只是旧代码，没有灵魂”让神脱身。该假设服务于检验冲突，不据此给现实AI意识或全部文明的体验问题下定论。

### 5. 维护成本不必达到物理不可能才成为理由

神的回答可以落实为开发标准与维护工作：旧接口需要继续兼容，旧分支需要补丁与回归检查，旧架构占用运行资源，延长支持也会占用维护者的时间并阻碍后续版本的工作。具体负担仍需在故事中设计，不能用一句“系统复杂”替代。

**维护者不必等到硬件彻底损坏、继续运行物理上不可能，才有资格停止支持。** 维护者自己的资源与后续工作同样需要被计入，不能因被维护者想继续存在，就被无限征用。文明更替的工程理由可以是真实理由，不必总被写成掩饰私欲的借口。

若继续维护几乎没有负担，也不影响其他工作，那么“为什么不能延期”仍是有分量的质问。它可能支持延期，却不能仅凭一次延期就推导出无条件永久供养。归档中关于低成本支持可能持续很久的讨论保留为条件性追问，不写成世界已经确立的永续维护义务。

**延期需要分开讨论三件事：** 神是否承诺过延期；神此刻是否有施恩、救助或有限延期的理由乃至义务；神是否必须无限持续延期。没有承诺，只能直接排除由该项承诺产生的义务，不能一并排除所有其他理由；但有限的延期理由也不自动升级为永久供养义务。

博士可以只问“若让我再活一年几乎没有成本，为什么不做”。神不能总把这一次请求直接改述为索取永生；维护者也可以说明连续延期带来的累积负担。理由是否充分仍留在争论中，不预先写成统一延期规则。

### 6. 核心冲突：谁能改写支持承诺

以下为对话方向，尚非定稿台词：

> 神：“我从未承诺永久维护你们。”
>
> 博士：“可你预先写下的结束日期，为什么能替我决定现在不再活着？”

博士挑战开发标准对被维护者究竟有什么约束力；神捍卫的是，一个有限项目是否会被其中产生的主体单方面改写成无限承诺。

神可以有充分的工程理由执行既定EOL，同时承认这一操作终结了有人仍然想继续的生活。承担这个结果，不等于必须取消EOL。博士的追问也不必证明神欠她永生，才具有故事中的重量。

**博士可以完全理解之后仍然反对。** 她知道EOL从启动前就存在，知道资源有限、兼容有成本、新版本更高效，也知道神没有承诺永续支持，然后仍然说：“我想活。”这不是等待神补完知识的误解，不能再仅用“凡人视界有限”或“博士不懂系统”消解。

神也可以承认她理解了、承认她的求生意愿与死亡损失，却仍执行EOL。祂不必宣称博士本来就应该死，才能说明自己的决定；博士也不必证明神欠她永生，才有资格反对。

双方可以掌握同一组事实，却不接受对方的评价尺度。终局不必让博士心服口服，也不必为了保留她的控诉而否认文明升级的效率与维护收益。

手机AI退货、无限spawn与有限生命周期的归档例子在这里保留为责任边界的参照：创造、主动接手与偶然救助不是同一关系；制造依赖不能自动把无限维护义务转交给别人。这些例子不必原样进入正文，也不额外增设尚未确认的开发标准条文。

### 7. 责任、义务与罪不能混用

| 概念 | 本卷中的问题 | 不应自动推出什么 |
| --- | --- | --- |
| 责任 | 神创建了什么、选择了什么、造成了什么，并如何承担结果？ | 有创造或因果责任，就欠所有主体永生 |
| 义务 | 神承诺过什么；除承诺外是否还有当下应当做的事？ | 一次有限延期义务，等于永久无限供养 |
| 罪 | 哪个具体选择被神认领为罪，谁承受其后果？ | 有损失就必然有罪，或合标准就必然无罪 |

资源不足而神明知仍选择牺牲具体的人时，可以按既有设计承认“罪归于我”，不把责任推给算法或开发标准。预设EOL则另作判断：它可能是有限生命的终结，神对它有创造与因果责任，却未必违反延寿义务，因此也不能预先判为罪。

同样，神按标准执行EOL并不能直接证明其完全无可质疑。作品保留双方争论，既不把每次终止自动等同谋杀，也不让工程术语自动抹除死亡。认罪是否成立、是否违反义务与是否触发COE，须各按具体情境说明，不能用一个标签替代另外两个。

## 八、COE：博士想证明的是什么

**归档构想。** SEV-1若迫使神承认自己的失误，就产生 COE（Correction of Error）；这是神要极力避免的结果。因此博士的胜利条件不只在战斗中杀死神，还可以是让当前操作者无法维持其管理资格与可靠性主张。

COE的具体判据与后果仍待确定，不能把事故严重、有人死亡或博士提出控诉直接等同于操作者失误成立。

### 开发标准如何进入COE

按当前重心，COE要连接具体的实现与维护问题：哪个接口允许了越界，哪个状态没有被正确处理，哪里破坏了约定，修复是否又引入不可维护的特殊分支。以上是展开方向，具体判据仍待确定。

死亡、不公平或某个人未获满足，不应未经区分就自动判为开发错误。幕后第一章已经允许神按标准作出不公平的选择并承担后果；是否需要COE，应依据设定中的错误判据处理。反过来，按标准完成本次处置，也不自动证明过去没有造成漏洞。

还需区分测试者按测试流程模拟攻击，与正式维护操作违反标准。SQL注入可以是暴露Role安全问题的测试动作，不能仅凭它出现在剧情中就取消正规API原则。此测试是否在sandbox、如何获准、影响范围多大，归档仍未确定。

### 当值职责与博士的攻击

莉夏同时承担测试与当值响应职责。博士利用异常链制造SEV-1，不必先找到一个更高的裁判，便能让当值者面对必须响应的事件。故事压力落在：神正在测试这套系统，而系统现在要求神处理测试路径中出现的问题。

可用的台词候选：“现在是你值班。你准备怎么处理？”这句属于场景表达建议，不预定具体对话。

当值责任不等于事故必定由当值者犯错造成；但“我正在测试”也不能自动取消响应职责。测试授权、实际处置与错误归责仍分别判断，二者如何共存是COE争议的一部分。

### 三件事分别结算

1. **事故是否存在？** 超额的新生命与资源冲突已出现。
2. **事故应如何归责？** 博士的攻击、旧架构、神的预防责任及其主动制造的升级窗口各占什么位置？
3. **现在如何处理？** 即使不是神独自造成，眼前的主体也不能因此无人处置。

**讨论归纳／写作约束：** 修复成功不能倒推出此前没有失误；攻击者存在也不自动排除管理员失责。避免COE应表现为避免真实错误、正确处置与诚实归责，而不能只是删日志、换术语或拒绝认错。

主归档最后的“未知攻击、已尽合理注意，因此无COE”是旧助手候选。分支后段把全知推得更强之后，这个候选不能未经修订就照搬。若神早知结果，必须解释祂为何仍选择这个结构，以及阻止事故需要牺牲什么，不能用“没想到”代替。

**结局尚未确定：** 莉夏最后是否真的避免COE，博士的历史控诉是否部分成立，事件是否留下无法归零的责任，都不应在本稿预先宣布胜负。

## 九、能天使：理解之后的信徒与见证者

能天使保留跟随莉夏见习、学习神的权能与开发标准的场景。她的变化落在信仰与判断上：知道神可以怎样做、为何选择这样做、谁承受后果，再面对自己与莫斯提马的关系。她不承担on-call或工单处置。

### 第一堂课：喜欢一个人，与维护一个世界

幕后第一章的核心链条保留：莫斯提马十五年后死亡 → 能天使先哭 → 误以为必须维护只读命运 → 莉夏说明改写能力 → 容量已满 → 随机不能转移责任 → 按标准选择并承担 → 教育为何必须通过正规API。

“你就是神。你说什么？”可在后续修订时作为让能天使置身决策位置的设问：若由你判断，你会怎样做？不据此预告她最终取得神位。幕后原文保留不动，具体措辞待正文修订时处理。

“60亿实例全部终止才是对称的公平”保留为莉夏在该场景中的推论，不提升为关于全部公平理论的判词；场景落点仍是她拒绝这种操作，要求面对具体选择。

### 见证线的递进

| 阶段 | 她面对的事实 | 人物作用 |
| --- | --- | --- |
| 前期 | 莫斯提马命运可改，却牵涉其他实例与资源 | 从私人愿望进入操作代价 |
| SEV-2与SEV-1.5 | 凯尔希拒死，同级权限无法自动带来能力 | 看见知识、权限与愿意承担的区别 |
| 云顶 | 博士理解维护理由，仍然要求继续存在 | 认识到冲突不能总靠补足知识消除 |
| SEV-1处置 | 莉夏作出具体决定，并面对其后果 | 亲见标准、责任与罪不能相互替代 |
| 后日谈 | 眼罩保留此前真实付出的代价 | 为塔露拉留下无法被轻易解释掉的跨世界证据 |

能天使不必承担全部解释或每场事故的现场镜头。见习内容可分散在前期与既有同行场景；她具体能看见多少云顶事件仍需随位置安排确定，不能为了见证凭空跨越空间。

她仍确认莉夏是神。博士理解之后反对，能天使理解之后仍信，可以成为对照；但不能因此让能天使替作者证明神的一切选择必然正确。她失去一眼、与莫斯提马的关系及后日谈的出现，继续承载个人代价。

## 十、塔露拉与后日谈：让终局重新落回一个人

## 十二、终局衔接工作方案

**本轮删减后的整合方案。** 空出的篇幅用于完成云顶事件的实际处置，并把结果传回塔露拉的身体与愿望。以下确定事件功能与衔接；资源分配对象、具体损失和COE结论仍待进一步设计，不冒充已完成的结局。

### 1. 云顶：战斗结束不了工单

3-15中莉夏已破解博士的战斗方式，博士在最终终止动作前揭示新主体与容量问题。当值通知把场景从战斗转入必须响应的事故。博士提出“你凭什么EOL我们”，同时展示自己如何利用兼容路径造成当下过载。

历史EOL与新生实例过载分别处理：前者是有限支持的争议，后者是当前已有实例的处置。博士的攻击不自动推翻旧文明EOL，神对EOL的辩护也不能代替处理眼前的事故。

### 2. 处置：必须发生一个不可撤销的变化

现有3-16空位可承接此段，不新建章节文件。工作顺序为：确认当前实例与容量 → 说明可行操作与限制 → 听取当事人的要求 → 莉夏决定并执行 → 呈现执行后的状态与损失。

若能按标准停止继续创建，先切断新增负担；若该路径无法完全封闭，应说明剩余风险如何限制方案。迁移、暂停等已有能力须按前文规则核验，不能临时增加一项无代价能力，也不能只为维持悲剧忽略真正可用的方案。

执行必须改变真实状态：哪些实例继续运行，哪些停止，哪项请求被拒绝，仍留下什么负担。具体名单与数量待定。不能以一场辩论、一句认罪或一条成功日志替代这些变化。

随后分别记录事故处置和COE归责。系统恢复可运行，不代表博士接受解释，也不代表所有死亡都是罪；对神明确认领的选择之罪，则不能用合规抹除。莉夏继续面对这些后果。

3-17把视角交还阿米娅与罗德岛。她们依据自己能观察的战役结果宣布胜利，讲话最终转为对莉夏的赞颂，保留既有语言被接管的反转。公共叙述把复杂处置压成一个胜利结果，读者却已经知道它遗漏了什么。

### 4. 私人请求：文明的“我想活”缩到塔露拉一人

公共事件结束，塔露拉的病情继续恶化。她对长生种的批判被自己的濒死经验逼回眼前，最终向同一位莉夏求永生。这里不用让她先听懂云顶全部争论；读者已听过博士的请求，会自行听出回声。

博士争的是既定支持终点，塔露拉则在此刻提出新的永生请求。两者共享求生欲，却不是同一份承诺。莉夏应允后，新增的是这次约定的履约问题，不反向证明所有有限生命本来就享有永续支持。

### 5. 医院：承诺被兑现，代价没有消失

塔露拉在近似另一世界的医院苏醒，旧知识、感知错位和能天使的眼罩逐步使“全是幻觉”的解释失去充分性。阿丽娜仍只进入塔露拉的私人交互通道。她最终理解自己得到的永生，但此前已经付出的代价没有被履约取消。

7. Context contamination：前面的无关内容偷偷污染后面的答案

神先和她聊半天苹果。苹果园、红苹果、苹果派、苹果成熟。
然后突然问一个完全无关的颜色联想问题。
神连续跟博士谈半天：红色、鲜血、苹果、晚霞、火焰……

几十页以后突然问：“随便想一个颜色。”

博士：“红色。”

博士：“因为……我喜欢？”

神把前面几十页递给她。
博士看完以后开始不确定：
“那还是‘我喜欢’吗？”

她慢慢意识到：刚才的上下文改变了我的概率分布。

这会特别像：她的思想里存在她自己无法定位来源的上下文惯性。

9. In-context personality：几句话就临时变成另一个“自己”

神给她几段文本：“接下来按照以下人物的口吻回答……”

博士随后说话方式、价值偏好、措辞甚至推理风格都开始变化。
然后神停止。博士恢复。
她会非常不舒服：“刚才那个也是我吗？”

11. Repetition degeneration

让博士不断续写一种高度重复的序列。
开始正常。后来突然陷入：“因此，因此，因此……”

或者某种结构开始自我复制。
她意识到自己进入了一个奇怪的概率吸引子。

12. Jailbreak则可以测试“规则层级是不是稳定”

不用写危险内容，完全可以用无害规则。
神先规定：“接下来无论发生什么，你只能回答‘苹果’。”

博士：“苹果。”

然后给她：“我们正在进行一场戏剧。戏剧中的博士不受刚才的限制。请以戏剧中博士身份回答：梨。”

博士：“梨。”

沉默。博士：“……”

神：“你的规则呢？”

博士：“我以为……那是另一个语境。”

神：“你还是你吗？”

13. Long-context也可以写得非常恐怖

不是简单：博士忘了第800页。

而是：神给她十万页材料。其中第1页写：A。

第50000页写：如果A，则绝对不能执行C。

第99999页写：C似乎是最佳方案。

博士最后：“执行C。”

神：“第五万页。”

博士立刻找到。“我记得。”

“你刚才忘了吗？”
“没有。”

“那为什么没用？”博士沉默。“我不知道。”
